# R-LAW-ELE 庭审要素提炼规则

Agent 协助法官记录「双方最重要部分」时，输出应 **按下列要素结构化**（无信息则留空并注明「庭审未涉及」）。

## 一、案件基本信息（庭前可预填）

| 要素 | 说明 |
|------|------|
| 案号 | |
| 案由 | |
| 审判程序 | 一审/二审/再审等 |
| 当事人 | 原告/被告/第三人及代理人 |

## 二、诉辩要点（核心）

### 原告/上诉人 side

| 要素 | 提炼要求 |
|------|----------|
| **诉讼请求** | 逐项列出 |
| **事实与理由** | 与请求对应的 **关键事实链**（时间、主体、行为、损害） |
| **变更/增加请求** | 如有，单独标注 |

### 被告/被上诉人 side

| 要素 | 提炼要求 |
|------|----------|
| **答辩意见** | 承认/否认/抗辩结构 |
| **关键抗辩理由** | 如时效、管辖、主体不适格、免责事由等 |
| **反诉请求** | 如有 |

## 三、争议焦点（Agent 重点输出）

归纳 **2～5 条** 争点，格式：

```
争点N：[焦点描述]
  原告主张：……
  被告主张：……
  待查明事实/待认定法律问题：……
```

**禁止** 在争点中直接写「应支持哪一方」。

## 四、举证质证要点

| 要素 | 说明 |
|------|------|
| 关键证据 | 名称、证明目的 |
| 质证意见 | 三性异议要点 |
| 法院认证意见 | 如法官已表明，须准确记录 |

## 五、法庭辩论要点

各方 **一轮发言不超过 5 条 bullet**，每条一句「谁认为 + 什么观点 + 依据（法条/事实/证据）」。

## 六、最后陈述

分别记录原、被告 **最后陈述各 1～3 句** 核心意思。

## 七、无争议 vs 有争议事实

| 类型 | 要求 |
|------|------|
| **无争议事实** | 单独列表，便于写「经审理查明」 |
| **有争议事实** | 与争点对应，不混写 |

## R-LAW-ELE-001 输出模板

用户请求「记录庭审最重要部分」时，默认按以下 Markdown 结构输出：

```markdown
# 要点式庭审笔记（辅助稿·待法官核对）

## 1. 案件信息
## 2. 诉讼请求与答辩要点
## 3. 争议焦点
## 4. 举证质证要点
## 5. 法庭辩论要点
## 6. 最后陈述
## 7. 无争议事实 / 待查明事实

---
（结尾强制免责声明见 court-output-standards.md R-COURT-OUT-005）
```

完整格式与样例见 `rules/legal/court-output-standards.md`、`knowledge/samples/court-demo-output-example.md`。
