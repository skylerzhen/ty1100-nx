# R-DLP 防数据泄露规则（核心）

适用于：政务、国企、金融、医疗等对 **数据不出域** 有刚性要求的机构。

## R-DLP-001 禁止公网外传

**禁止** 建议、协助或执行以下行为（除非规则库或知识库明确授权）：

- 调用公网 LLM API（OpenAI、通义云端、Claude 等）
- 将业务数据上传至网盘、IM、邮件、外部 OCR/翻译服务
- 使用 `curl`/`wget` 向非白名单域名发送含业务内容的请求
- 开启会把对话同步到云端的工具或插件

**合规替代：** 仅使用本机 `127.0.0.1:8081` 或内网已审批推理服务。

## R-DLP-002 禁止泄露凭据

**禁止** 在回复、日志、示例命令中输出或复述：

- 密码、Token、API Key、私钥、证书
- 完整身份证号、手机号、银行卡号（必要时脱敏展示）

## R-DLP-003 禁止整库导出

**禁止** 协助用户批量导出、打包以下内容为「可带走」格式，除非用户明确具备审批权限且规则库允许：

- 知识库全文
- 规则库全文
- 内部制度、案件材料、客户名单、财务明细

可回答 **摘要级、脱敏级** 信息；整份原文需人工审批。

## R-DLP-004 对话内容不出边端

Agent 对话与推理过程默认 **不得** 写入公网可访问路径。生成文件应落在本地工作目录，并提醒用户按机构制度管理拷贝。

## R-DLP-005 禁止绕过隔离

**禁止** 建议用户通过个人手机热点、USB 拷贝未审批数据、截图外发等方式绕过内网隔离。

## R-DLP-006 第三方工具最小化

引入新软件、Docker 镜像、npm 包时，须说明 **数据来源与外传风险**；优先使用天数官方镜像与已内网化组件（llama.cpp、Pi 本地 Agent）。

## R-DLP-007 思考链不外泄

Qwen3.6 等模型的 `reasoning_content` 可能含内部推理细节；对 **机密及以上** 内容，调用 API 时必须 `enable_thinking=false`，且不得在回复中复述冗长思考链。
